Escopo
- O projeto continua sendo um criador de posts, stories e landing pages; não é um sistema de agendamentos.
- A arquitetura segue o padrão solicitado, sem SQS: a publicação é síncrona.
- Supabase não faz parte da nova aplicação. Os arquivos do protótipo anterior foram preservados como legado, sem uso pelos builds novos.
- Os arquivos estáticos antigos na raiz e em projetos\ foram mantidos para preservar o histórico e os links existentes. Não são o novo painel.
- Nenhum banco foi criado em um provedor, nenhum Firebase foi configurado automaticamente e esta migração não foi enviada para produção.

Requisitos
- Node.js 24 LTS e npm.
- SDK .NET 10. O backend\global.json indica o SDK usado nos testes.
- PostgreSQL 17 local; Docker Desktop com Compose e opcional.
- Projeto Firebase com Authentication > Email/Password habilitado.
- Uma senha de banco forte e exclusiva, nunca incluída no Git.

Configurar Firebase
1. Crie um projeto no console Firebase e registre um aplicativo Web.
2. Em Authentication > Sign-in method, ative Email/Password.
3. Configure os domínios autorizados (localhost para testes e o domínio real do painel).
4. Configure os modelos/endereços de e-mail de confirmação e recuperação no Firebase.
5. A configuração Web do Firebase é pública. Ela não é uma credencial de administrador.
6. Copie .env.example para .env e preencha:
   FIREBASE_PROJECT_ID e VITE_FIREBASE_PROJECT_ID: o mesmo Project ID.
   VITE_FIREBASE_API_KEY, VITE_FIREBASE_AUTH_DOMAIN: dados públicos do aplicativo Web.
   POSTGRES_PASSWORD: senha do PostgreSQL, privada (somente para Docker).
- A API valida tokens assinados pelo Firebase e exige email_verified=true. Nunca use uma chave privada de service account no frontend.
- Após confirmar o e-mail, saia e entre novamente para obter um token atualizado.
- As operacoes online renovam o token antes de chamar a API para reconhecer a confirmacao do e-mail. Sem confirmacao, o painel orienta reenviar o link em Minha conta em vez de enviar uma requisicao que receberia 403.
- Para produção, revise cotas, proteção contra abuso e políticas do Firebase antes de liberar cadastros ao público.

Executar com Docker (a partir desta pasta)
  docker compose up --build -d

Endereços locais:
  Painel: http://localhost:5173
  Site público: http://localhost:3000
  API e saúde: http://localhost:5080/health
- O Compose só expõe portas no localhost. Não é uma configuração pronta de produção.
- O PostgreSQL persiste no volume postgres-data. Parar os contêineres não apaga os projetos.
- A API executa as migrations ao iniciar no Compose. Em produção, prefira aplicá-las como uma etapa controlada de release.
- Variáveis VITE_ entram no build do painel: para alterá-las, reconstrua a imagem.

Executar separadamente neste Windows (sem Docker)
- O PostgreSQL fica em %LOCALAPPDATA%\AtelieAlexandra, com dados persistentes em data\.
- Aceita conexoes somente locais na porta 5432; a aplicacao usa o usuario atelie, sem privilegios de superusuario.
- As credenciais app-credential.xml e admin-credential.xml sao criptografadas pelo Windows e so podem ser abertas pelo mesmo usuario neste computador. Nunca envie esses arquivos para o Git.
- O banco nao e um servico do Windows e nao inicia automaticamente apos reiniciar o computador.
- Na raiz do projeto:
  powershell -ExecutionPolicy Bypass -File .\scripts\local.ps1 start-db
  powershell -ExecutionPolicy Bypass -File .\scripts\local.ps1 migrate
- Em terminais separados:
  powershell -ExecutionPolicy Bypass -File .\scripts\local.ps1 api -FirebaseProjectId SEU_PROJECT_ID
  powershell -ExecutionPolicy Bypass -File .\scripts\local.ps1 dashboard
  powershell -ExecutionPolicy Bypass -File .\scripts\local.ps1 landing
- O comando api exige o ID real do Firebase; preencha tambem a configuracao Web em .env para habilitar o login no painel.
- Ctrl+C encerra a API ou frontend do respectivo terminal. Para parar o banco:
  powershell -ExecutionPolicy Bypass -File .\scripts\local.ps1 stop-db
- Parar o banco nao apaga os dados. Nao remova a pasta data\. Faca backups antes de trocar de computador ou reinstalar o Windows: as senhas criptografadas nao sao portaveis.

Executar os frontends manualmente sem Docker
  npm ci
  npm run dev:dashboard
  npm run dev:landing
- O Vite lê .env da raiz. A landing usa API_INTERNAL_URL no ambiente do processo; por padrão aponta para http://localhost:5080.
- O editor e downloads locais funcionam sem conta/API configurada.
- Para o site consultar a API no servidor Docker, API_INTERNAL_URL é http://api:8080 (configurado no Compose). Não use esse hostname nas URLs públicas do navegador.

Executar a API sem Docker
- Inicie um PostgreSQL real e configure, no ambiente do processo:
  ConnectionStrings__Postgres=Host=localhost;Port=5432;Database=atelie;Username=atelie;Password=SUA_SENHA
  Firebase__ProjectId=SEU_PROJECT_ID
- A partir de backend\:
  dotnet tool restore
  dotnet ef database update --project src\Cartao.Api
  dotnet run --project src\Cartao.Api --urls http://localhost:5080
- CORS permite http://localhost:5173 por padrão. Para outro domínio, defina Cors__AllowedOrigins__0 (e índices adicionais).
- O Next consulta a API no servidor; não exige CORS para a chamada interna.
- Não há login falso nem bypass de autenticação quando o Firebase está sem configuração.

Fluxo de trabalho
EDITOR VISUAL
- Posts e Stories: escolha Editorial, Impacto ou Essencial, ou comece em branco.
- Projetos antigos mantem o layout original ate escolher um modelo ou adicionar uma camada.
- Camadas: varias fotos, textos, retangulos e elipses; selecao, arraste, redimensionamento pelo canto e posicoes numericas.
- + Forma abre uma selecao de retangulo, elipse, triangulo, losango, estrela, hexagono, seta e balao. Nas propriedades, ative "Texto dentro da forma" para escrever nela e ajustar fonte, cor e margem interna. Texto excedente e limitado ao contorno da forma.
- Caixas de texto aceitam fundo colorido, cantos arredondados, margem interna, borda e sombra. Formas tambem aceitam borda e sombra; cantos arredondados se aplicam a retangulos e baloes. Efeitos ficam no PNG, no JSON e no salvamento online; projetos antigos mantem a aparencia.
- Texto: ao adicionar uma caixa, digite diretamente na arte. Dois cliques, Enter/F2 ou "Escrever na caixa de texto" iniciam a edicao; Esc ou clique fora encerra. O campo Texto das propriedades continua disponivel. Camadas bloqueadas nao permitem edicao.
- Alcas no meio das laterais ajustam somente a largura; em cima/baixo ajustam somente a altura. O canto ajusta ambas. Funcionam tambem em elementos girados e com desfazer/refazer.
- Novas fotos usam "Largura e altura independentes (sem cortar)": a lateral altera apenas a largura visivel, cima/baixo apenas a altura, mesmo deformando a proporcao. Fotos no modo inteiro ou sem modo definido passam a esse ajuste ao redimensionar. "Foto inteira" preserva a proporcao dentro da caixa ate o proximo redimensionamento. "Preencher e recortar" preserva o recorte dos modelos.
- O gesto termina ao soltar o mouse, cancelar o toque ou trocar de janela. Clique no centro para selecionar/mover; arraste uma alca para redimensionar. Um clique sem arraste nao muda o tamanho.
- No modo "Preencher e recortar", alterar a caixa muda o enquadramento; use zoom e deslocamento para ajustar o recorte. No modo independente, a foto inteira ocupa a caixa e nao usa zoom/deslocamento.
- Propriedades: tamanho, rotacao, opacidade, ordem, bloqueio, duplicacao, fontes, alinhamento e cores.
- Fotos: enquadramento com zoom e deslocamento, cantos arredondados, brilho, contraste, saturacao e filtros basicos. Nao usa IA.
- Textos longos sao limitados pela caixa: aumente a altura para mostrar mais linhas.
- Desfazer/refazer guarda ate 30 estados da composicao durante a sessao; atalhos Ctrl+Z, Ctrl+Shift+Z e Ctrl+D.
- As setas movem a camada selecionada em 1 px; Shift+seta move em 10 px.
- Landing pages: modelo responsivo com blocos de capa, apresentacao, servicos, foto e contato; personalize e reordene em Blocos.
- O botao de contato usa o WhatsApp definido em Conteudo. A previa de landing oferece Desktop e Celular.
- O editor preserva o trabalho ao alternar entre Editor, Meus projetos e Minha conta. Abrir outro projeto substitui o atual.
- Antes de fechar ou recarregar, salve online ou baixe o projeto JSON. Fotos e camadas nao sao salvas automaticamente no navegador.
- Limites: 40 camadas, 16 blocos, 12 servicos por bloco; PNG de ate 5 MB por foto e projeto JSON de ate 7,5 MB no total.
- JSON v1 continua abrindo; composicoes e blocos novos usam JSON v2 e exigem esta versao do editor para reabrir sem perdas.
- Exportacao PNG usa o mesmo renderizador da previa, sem bordas de selecao. HTML baixado inclui as fotos e os blocos.
- Camadas e blocos sao armazenados em values.design e values.landing (JSONB), junto ao rascunho e ao snapshot publicado. Nao exige migration de tabela.
- Para publicar esta atualizacao, implante primeiro a API e depois painel e landing. A API antiga rejeita os novos campos.

1. Entre no painel e crie sua conta; confirme o e-mail.
2. Edite texto, cores e foto. A prévia de post/story é o mesmo canvas usado no PNG baixado.
3. Salvar projeto baixa um JSON com textos e foto; Abrir projeto JSON importa inclusive arquivos da versão antiga.
4. Baixar imagem JPG gera 1080 x 1080 ou 1080 x 1920 em arquivo otimizado. A landing pode ser baixada como HTML independente com foto incluída e otimizada.
5. Salvar online mantém um rascunho privado no PostgreSQL, separado por conta Firebase.
6. Defina um endereço único, confirme a autorização da foto e clique em Publicar / atualizar landing.
7. Compartilhe http://localhost:3000/projetos/seu-endereco apenas em testes locais. Em produção, o link usa VITE_PUBLIC_SITE_URL e pode ser aberto sem login.
8. Meus projetos lista apenas projetos da sua conta.
9. Criar outra landing desvincula o editor do projeto anterior. A próxima gravação cria uma cópia.
10. Salvar rascunho não altera a publicação. Publicar faz um snapshot dos textos e da foto.
11. Retirar do ar remove a publicação, sem apagar o rascunho. Excluir projeto exige confirmação e remove ambos.
- Edições concorrentes são rejeitadas com conflito; reabra o projeto para carregar a revisão mais recente.
- Fotos são normalizadas para PNG de até 1920 px e 5 MB. No banco, são armazenadas junto ao projeto/snapshot.
- Para simplificar esta primeira migração, a lista retorna fotos inline e pode ficar grande; não há paginação ou armazenamento externo de mídia ainda.
- O editor guarda textos localmente no navegador e a foto somente ao salvar um projeto. Saia e feche o editor em computadores compartilhados.

Migrar os projetos já salvos
- Abra seu projeto-alexandra.json antigo no novo painel, entre na sua conta e clique em Salvar online.
- Publique com o endereço desejado.
- O catálogo estático antigo não é importado automaticamente para contas do Firebase.
- Não há conversão automática de usuários ou dados do protótipo Supabase. Se houver dados reais ali, exporte-os antes de desligar o serviço.

Publicar na internet
- O render.yaml cadastra API Docker Free, site Next Docker Free e painel estatico. O build Docker e feito no Render, sem precisar instalar Docker neste computador.
- Use Render > New + > Blueprint e selecione o repositorio com esta versao. Confirme que ambos os Web Services estao no plano Free e que nao ha banco Render pago sendo criado.
- Nunca coloque a senha Neon no render.yaml. Na variavel privada ConnectionStrings__Postgres da API, use o formato Npgsql (nao a URL postgresql://):
  Host=HOST_DO_NEON;Port=5432;Database=neondb;Username=neondb_owner;Password=SENHA_DO_NEON;SSL Mode=Require;Channel Binding=Require
- Preserve o host exato mostrado no Neon. Para migrations, prefira a conexao direta (desative Connection pooling em Connect); mantenha TLS habilitado.
- Firebase__ProjectId na API e VITE_FIREBASE_PROJECT_ID no painel: ID real do mesmo projeto Firebase.
- Apos o Render atribuir as URLs HTTPS reais, ajuste as variaveis (nao suponha que os nomes estejam disponiveis):
  API: Cors__AllowedOrigins__0 = URL HTTPS do painel, sem barra final.
  Site Next: API_INTERNAL_URL = URL HTTPS da API.
  Painel: VITE_API_URL = URL HTTPS da API; VITE_PUBLIC_SITE_URL = URL HTTPS do site Next.
  Painel: VITE_FIREBASE_API_KEY e VITE_FIREBASE_AUTH_DOMAIN = configuracao Web do Firebase.
- As URLs devem ser completas com https://. Nao use localhost em producao. Reconstrua o painel apos mudar variaveis VITE_.
- No Firebase > Authentication > Settings > Authorized domains, adicione o hostname do painel Render (sem https://).
- A API aplica migrations ao iniciar nesta configuracao inicial. Os projetos do banco local nao sao copiados: importe seus JSONs no painel online e salve/publice novamente.
- Confirme /health da API com Healthy, crie/acesse uma conta com e-mail verificado, salve e publique; teste a URL /projetos/slug em outro dispositivo sem login.
- Os servicos Free dormem apos inatividade, compartilham as 750 horas mensais e podem demorar cerca de um minuto para despertar. As chamadas a API aguardam ate 90 segundos; isso nao evita cotas, indisponibilidade ou outros limites do provedor.
- O PostgreSQL Neon Free tem cotas de armazenamento/compute; fotos inline consomem espaco. Mantenha backups e monitore o consumo. Nao use o PostgreSQL Render Free como armazenamento permanente: expira apos 30 dias.
- GitHub Pages não executa esta API nem o servidor Next.js. O simples push não coloca a aplicação nova no ar.
- Hospede API e Next em um serviço com suporte a .NET/Node ou contêineres e use PostgreSQL gerenciado ou persistente.
- O painel Vite pode ser servido estaticamente por Nginx (Dockerfile incluído).
- Configure HTTPS, domínios públicos e backups. Atualize VITE_API_URL, VITE_PUBLIC_SITE_URL, API_INTERNAL_URL, os domínios Firebase e CORS.
- Não exponha PostgreSQL publicamente nem disponibilize .env.
- As landings Next são renderizadas no servidor, com título/descrição individuais e resposta 404 para páginas retiradas. Não é necessário JavaScript no cliente para ler o conteúdo.
- O caminho público é /projetos/endereco. Links GitHub Pages antigos continuam sendo da versão estática, não apontam automaticamente ao servidor novo.
- SQS não foi incluído. Não há painel de administrador para ver projetos privados de outros usuários.
